# 07 — Internationalization (EN / VI / JA)

Baseline matches the portfolio standard: **English (default), Vietnamese,
Japanese**. Two mechanisms with a strict split:

| Layer | Mechanism | Why |
|---|---|---|
| Manifest strings (name, description) | `chrome.i18n` + `_locales/` | Required by CWS for localized store/manifest fields; follows the *browser* UI language. |
| All in-app UI strings | Custom runtime store (`src/lib/i18n/`) | Users must be able to switch language **in Settings**, independent of browser language — `chrome.i18n` cannot do that. |

## 1. `_locales/` (manifest-level only)

```
public/_locales/en/messages.json   ← default_locale
public/_locales/vi/messages.json
public/_locales/ja/messages.json
```

```json
{
  "appName":  { "message": "BookmarkMagic" },
  "appDesc":  { "message": "Import, export & edit bookmarks between browsers — offline, no account, no cloud." }
}
```

`wxt.config.ts` manifest: `name: "__MSG_appName__"`,
`description: "__MSG_appDesc__"`, `default_locale: "en"`.
Keep `appName` identical in all three locales (brand name is not translated);
`appDesc` is translated.

## 2. Runtime i18n — `src/lib/i18n/`

```ts
// locales/en.ts  (vi.ts, ja.ts mirror the exact same shape)
const dict = {
  common: { import: 'Import', export: 'Export', edit: 'Edit',
            settings: 'Settings', about: 'About', cancel: 'Cancel', /* … */ },
  import: {
    dropHint: 'Drop a bookmark file or {browse} — .html, .json, .csv · max {size}',
    stats: { bookmarks: '{n} bookmarks', duplicates: '{n} duplicates found' },
    mode: { newFolder: 'Into a new folder (recommended)', merge: 'Merge into existing folders',
            replace: 'Replace everything' },
    replaceWarning: 'This deletes ALL current bookmarks. A JSON safety backup will download first.',
    progress: 'Importing… {done} / {total}',
  },
  /* export, edit, settings, about, legal, errors … */
};

export default dict;
export type Dict = typeof dict;      // widened: string, NOT the literal 'Import'
```

```ts
// locales/vi.ts  (ja.ts identical in shape)
import type { Dict } from './en';
export default { /* … */ } satisfies Dict;
```

```ts
// index.svelte.ts
import en from './locales/en'; import vi from './locales/vi'; import ja from './locales/ja';
export type Locale = 'en' | 'vi' | 'ja';
const dicts = { en, vi, ja };
let locale = $state<Locale>('en');                 // hydrated from settings store
export function t(path: string, params?: Record<string, string | number>): string
// resolves dotted path in dicts[locale], falls back to en, interpolates {tokens}
export function setLocale(l: Locale) { locale = l; }  // settings store persists
```

- `en.ts` is the **schema source of truth**; `vi`/`ja` are typed
  `satisfies Dict` → missing keys fail `tsc` (compile-time completeness check,
  no i18n framework needed).
- ⚠️ **Do not write `as const` on `en.ts`.** It would make `typeof dict` a tree
  of *string literal* types, so `satisfies Dict` would demand
  `vi.common.import === 'Import'` — every correct translation becomes a compile
  error and the only way to make VI/JA build is to leave them in English.
- `Dict` is exported from `locales/en.ts` (a leaf module), **not** from
  `index.svelte.ts`. That module imports vi/ja and holds runtime `$state`, so
  having vi/ja import a type back from it forms a cycle that is only harmless
  while the import stays type-only — fragile under `verbatimModuleSyntax`.
- Interpolation is `{token}` replacement only. **No string concatenation of
  sentence fragments** — full sentences per key, so VI/JA word order works.
- Initial locale resolution: saved setting → else map
  `chrome.i18n.getUILanguage()` prefix (`vi*`→vi, `ja*`→ja) → else `en`.

## 3. Formatting rules

- Dates in UI: `new Intl.DateTimeFormat(localeTag, { dateStyle:'medium', timeStyle:'short' })`
  with tags `en-US` / `vi-VN` / `ja-JP`.
- Numbers (counts): `Intl.NumberFormat(localeTag)` — VI uses `.` thousands.

Where these live: pure `localeTag` / `formatCount` / `formatDateTime` in
`src/lib/i18n/format.ts` (formatters cached per tag — `StatsCard` alone formats
four counts per paint), plus reactive `num()` / `dateTime()` wrappers in
`index.svelte.ts` that read the current locale. `formatDateTime` returns
`undefined` rather than a string on an unparseable input: `readLegal` coerces a
missing `acceptedAt` to `''`, and `Intl.format(new Date(''))` throws a
`RangeError` *inside a render*, which would blank the About tab.

Three rendered numbers deliberately do **not** go through `num()`, each with a
comment at the site so the next reader does not "finish the job":

| Site | Why |
|---|---|
| `ProgressBar`'s `{n}%` | 0–100; no locale groups two digits, and it is the hottest render path in the app |
| `import.folderName`'s date | this bullet list already pins it to the localized *word* + an **ISO** date; localizing it would rename folders written into the user's browser |
| Export filenames and file contents | locale-independent so a file means the same thing whoever opens it |

ARIA numeric attributes (`aria-level`, `aria-valuenow`) are not display text and
stay raw.
- File names & file contents stay locale-independent (ISO dates, English
  "Imported" folder prefix? **No** — the auto-folder title uses the localized
  word + ISO date, e.g. `Đã nhập 2026-07-03`, key `import.folderName`).

## 4. Translation workflow & tone

- New strings land in `en.ts` first (PR fails type-check until vi/ja follow).
- VI: neutral–friendly register, "bạn"; keep established loanwords
  (bookmark, import/export may stay English in UI where natural — decide per
  string, be consistent; folder = "thư mục").
- JA: です/ます form; katakana loanwords (ブックマーク, インポート,
  エクスポート, フォルダ).
- No machine-translated commits without human review (owner reviews VI;
  JA reviewed best-effort — mark `// TODO(review-ja)` where unsure).

## 5. Locale-sensitive edge cases

- Pluralization: plural keys are objects `{ one, other }` in **every** locale —
  a tiny helper selects by locale. VI/JA have one grammatical form, so they set
  `one` and `other` to the same string. They must still carry both keys, or the
  `satisfies Dict` shape check that §2 relies on for completeness fails.

  Implemented as `selectPluralForm(count, tag)` in `i18n/format.ts` (backed by
  `Intl.PluralRules`, narrowed to the two forms — en yields `one`/`other`, vi
  and ja only ever `other`, so two forms cover every locale we ship) and
  `tPlural(path, count, params?)` in `index.svelte.ts`, which supplies `{n}`
  already grouped for the locale so callers pass a raw count. Two tests in
  `tests/unit/i18n/dictionaries.test.ts` enforce the shape: every plural key
  carries both forms in all three locales, and carries nothing else.

  The current plural keys are `import.warnings.title` and **all seven**
  `warnings.*` codes — including the two that interpolate no count, because
  `ParseWarning` always carries one and a uniform shape lets `WarningList` call
  `tPlural` unconditionally instead of maintaining a list of which codes count
  things. Anything else stays a plain string.
- Legal Gate: the four legal documents are **English-only** (canonical), with
  a localized one-line note: "The legally binding documents are in English."
- Store listing: EN required; VI + JA listings via CWS dashboard localized
  fields (copy lives in `13_RELEASE_PUBLISHING.md`).
